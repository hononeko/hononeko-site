Media server telemetry

miru

Lightweight, security-hardened media server telemetry, live stream monitor, playback history tracker, and library analytics. Built with Kotlin, Ktor, Arrow-kt, and a SvelteKit PWA in a 70.7 MiB Distroless container.

docker run -d --name miru -p 8080:8080 -e AUTH_SESSION_SECRET="$(openssl rand -base64 48)" -e MIRU_ENCRYPTION_KEY="$(openssl rand -base64 48)" -v miru-data:/data ghcr.io/hononeko/miru:latest
View on GitHub Kubernetes guide

Installable SvelteKit PWA, dark and light

Live sessions, history, user scoping, and library insights adapt cleanly to mobile screens in both dark and light themes.

Built for Plex, typed end to end

A Kotlin 2.4 / Ktor 3 API with Arrow-kt typed errors and an OpenAPI 3.1 contract, bundling a static SvelteKit 2 + Svelte 5 frontend into one hardened container.

Real-time Plex monitoring

Listens on Plex's WebSocket notification stream with debounced updates and exponential backoff, paired with a fallback polling reconciler and SSE live push.

Playback history & RBAC scoping

Records play sessions with resume-window merging, watch thresholds, and Tautulli SQLite import. Link USER accounts to Plex users to scope views, metadata, and artwork.

Library codec & growth analytics

Break down library sections by video codec, resolution, audio format, stale storage, and item growth over time across movies, TV shows, and episodes.

OIDC, local & API key auth

Run with Argon2id local login, PKCE S256 OIDC single sign-on (or hybrid mode), rate limiting, and SHA-256 hashed miru_... API keys for automation.

SQLite & PostgreSQL parity

Start immediately with embedded SQLite, or point DB_ENGINE=postgres at PostgreSQL. Both engines share Flyway migrations and Exposed repositories.

Distroless container & OpenAPI 3.1

Ships in a 70.7 MiB shell-less Distroless jlink image serving the built SvelteKit PWA alongside /healthz, /readyz, and /api/v1/openapi.yaml.

Measured against Tautulli

Side-by-side containerized benchmarks on a shared 10,000-play dataset under identical 2 vCPU / 512 MiB limits against Tautulli v2.19.1.

18× Faster live UI updates

526–528 ms via WS + SSE vs. 9.5 s polling, with 7.4× less 30s live traffic.

12× Higher history throughput

642 req/s (11 ms p50) on PostgreSQL vs. 53 req/s (165 ms p50) at 10 clients.

15× Faster cached artwork

5,482 req/s (1.56 ms p50) from memory vs. 370 req/s (29.3 ms p50) on disk.

70.7 MiB Distroless image (amd64)

181 MiB unpacked — 39% smaller than Tautulli's 296 MiB unpacked image.

Hardened by default

Plex tokens, sessions, and outbound fetches stay behind a single typed Ktor boundary. Every control is source-verified in docs/security.md.

Auth, rate limits & section RBAC

Argon2id hashing with a 4-way concurrency cap, bounded per-IP and per-account rate limiting, proxy-aware Secure HttpOnly cookies, asymmetric PKCE S256 OIDC, and fail-closed Plex library-section RBAC across metadata, artwork, and SSE.

CSP, encrypted secrets & SSRF defense

Global security headers with startup SHA-256 CSP script hashes, AES-256-GCM encrypted Plex tokens that never reach the browser, DNS public-IP validation with socket-pinned HTTPS avatar fetches, XXE-disabled XML parsers, and read-only 256 MiB capped SQLite imports.

Distroless & supply-chain gates

Digest-pinned shell-less Distroless + 14-module jlink runtime as UID 10001 with --read-only and /tmp:noexec, Kubernetes restricted PSS manifests, blocking Trivy CVE scans, CodeQL, and GHCR Artifact Attestations.

Quick start

Run the multi-arch container image with Docker Compose and SQLite, then open http://localhost:8080, create the first admin account and connect Plex from Admin. For Kubernetes, start from the example Kustomize manifests in docs/k8s/. Every setting is listed in the environment variable reference.

$ mkdir miru && cd miru
$ curl -fsSLO https://raw.githubusercontent.com/hononeko/miru/main/docs/docker-compose.yml
$ cat > .env <<EOF
AUTH_SESSION_SECRET=$(openssl rand -base64 48)
MIRU_ENCRYPTION_KEY=$(openssl rand -base64 48)
EOF
$ docker compose up -d   # SQLite on a named volume; see the file for PostgreSQL
